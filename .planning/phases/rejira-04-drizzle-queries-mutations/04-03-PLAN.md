<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → RSC page | The `params.key` and `params.id` come from the URL — untrusted. `getProjectByKey` returns null on miss, and the page calls `notFound()` |
| RSC page → DB | The RSC helper is wrapped in `requireAuth()`; the active workspace is resolved from the session. RLS denies cross-workspace reads regardless |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-15 | Spoofing | params.key in [key] route | mitigate | getProjectByKey returns null on miss; page calls notFound(). RLS denies the query if the user is not a member of the project workspace |
| T-04-16 | Information Disclosure | Cycle board with cross-workspace cycleId | mitigate | getIssuesForActiveWorkspace({ cycleId }) filters by active workspace; RLS denies cross-workspace reads |
| T-04-17 | Tampering | assigneeId filter bypass | mitigate | The RSC helper joins memberships to filter by user externalId; RLS denies cross-workspace reads; the page calls requireAuth() before reading |
| T-04-18 | Information Disclosure | Type barrel exposing PII fields | mitigate | The types re-exported from @/lib/db/types are field-level; the page does not render sensitive fields (email, password hash, etc. — those are in the auth.* tables, not business tables) |
| T-04-19 | Denial of Service | My Issues page rendering 10k rows | mitigate | RSC helper accepts a `limit` (default 500); the page passes `limit: 500`; the grouped-list virtualizes beyond 200 rows |
</threat_model>
