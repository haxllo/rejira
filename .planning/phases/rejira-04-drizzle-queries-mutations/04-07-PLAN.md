Prove that RLS is the only authorization boundary. Delete every app-level guard that tries to enforce tenancy or role. Extend the Phase 2 pgTAP suite with negative cases for every business table; the CI gate fails the build on regression.

Purpose: Defense in depth. Even if a developer adds a bug in app code that tries to query another workspace's data, RLS denies it at the database. The pgTAP suite is the contract. Deleting the Convex-era `requireRole` helpers is the discipline — we don't *both* RLS and `requireRole`; we use RLS only.
Output: 2 new pgTAP test files, 1 deleted file (rbac-helpers.ts), 1 bash script that greps for forbidden patterns, 1 Vitest integration test, 1 CI workflow update.

**Step 1: Create `supabase/tests/04-rls-cross-tenant.test.sql`.**

This is a pgTAP test file. The pattern is:
- `BEGIN;`
- `SELECT plan(N);`
- For each test case: `SELECT is(actual, expected, 'test description');`
- `SELECT * FROM finish();`
- `ROLLBACK;` (pgTAP rolls back the test data)

The test must:
- Set up 2 test workspaces, 2 test users (one in each workspace)
- Set `request.jwt.claims` to user A's claims (via `set_config('request.jwt.claims', json_build_object('sub', 'user-a-external-id', 'workspace_id', 'ws-x')::text, true)`)
- Run SELECTs and DML on workspace Y's tables
- Assert 0 rows (SELECT) or 0 affected rows (UPDATE/DELETE) or error (INSERT)

For each of the 9 business tables (issues, projects, cycles, labels, comments, notifications, saved_views, activities, memberships):
- Test SELECT: `SELECT count(*) FROM public.{table} WHERE workspace_id = 'ws-y'::text;` (the column is text in some tables, bigint in others — verify each)
- Test UPDATE: `WITH updated AS (UPDATE public.{table} SET ... WHERE workspace_id = 'ws-y'::text RETURNING 1) SELECT count(*) FROM updated;` (assert 0)
- Test INSERT: `INSERT INTO public.{table} (workspace_id, ...) VALUES ('ws-y', ...);` (assert raises insufficient_privilege)

Total: 9 tables × 3 ops = 27 cases minimum; spec says 20+.

**Step 2: Create `supabase/tests/04-rls-mutations.test.sql`.**

Tests the role-based mutations:
- A non-admin member tries `UPDATE public.memberships SET role = 'owner' WHERE id = $1;` (assert 0 rows affected; or raise)
- A guest tries `SELECT * FROM public.projects WHERE visibility = 'private' AND workspace_id = $1;` (assert 0 rows; the `visibility` column may not exist — verify the projects schema; if absent, use a different private-only mechanism, e.g. private saved views)
- A non-owner member tries `DELETE FROM public.workspaces WHERE id = $1;` (assert 0 rows)
- An issue creator can update their own issue; a non-creator non-admin member can update any issue in the workspace (RLS on UPDATE for issues is workspace-scoped, not creator-scoped)
- A user not in the workspace cannot insert a saved_view with workspace_id = X

Spec says 10+ test cases.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App code → DB | App code passes a JWT via set_config; RLS reads the JWT and evaluates policies. There is NO second-line check in app code |
| Test setup → DB | The test must set the JWT GUC per-transaction to simulate a different user; if the GUC leaks across transactions (i.e. set with `false` as the third arg), the tests would falsely pass |
| CI gate | The pgTAP tests are the contract; if they fail, the build fails. No way to merge a regression |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-41 | Tampering | Test setup leaking JWT context across tests | mitigate | Every pgTAP test wraps in `BEGIN; ... ROLLBACK;`; the `set_config(..., true)` is transaction-local; the test database is reset before each test file |
| T-04-42 | Spoofing | A developer adds a new `requireRole` helper | mitigate | `check-rbac.sh` runs in CI and fails the build on any forbidden pattern |
| T-04-43 | Elevation of Privilege | A policy regression lets a non-admin promote themselves | mitigate | The pgTAP mutation test asserts the UPDATE returns 0 rows; CI fails on regression |
| T-04-44 | Information Disclosure | RLS policy accidentally grants SELECT on a private table | mitigate | The pgTAP cross-tenant test asserts SELECT returns 0 rows from a workspace the user is not a member of; CI fails on regression |
| T-04-45 | Repudiation | Test data left behind in the local Supabase | mitigate | The test wraps in BEGIN/ROLLBACK; the test database is reset before each test file |
</threat_model>
