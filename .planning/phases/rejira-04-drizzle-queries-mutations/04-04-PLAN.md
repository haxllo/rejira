<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → RSC page | params.id, params.key, searchParams are untrusted. getSavedViews + filter decoding happen server-side; the page calls notFound() on miss |
| Server action → DB | Every action runs inside withWorkspaceTransaction; the actor is the session user, not the URL |
| Local storage | The saved-views store no longer reads from localStorage; the only persisted state is the Zustand store, which is rebuilt from Drizzle on every mount |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-20 | Spoofing | view.filter JSON could reference a different workspace's projectId | mitigate | The view's filter is decoded server-side; getIssuesForActiveWorkspace filters by the active workspace; RLS denies cross-workspace reads |
| T-04-21 | Tampering | savedViews store stale data after a write | mitigate | After every createSavedView / updateSavedView server action, the page calls `router.refresh()` (Server Component re-render) which re-reads getSavedViews() |
| T-04-22 | Information Disclosure | Members page exposing emails | mitigate | The members page is gated to admins/owners (RLS on the page or the surrounding route); emails are only shown to users who can see them. Verify the existing route protection from Phase 3 covers this |
| T-04-23 | Repudiation | Activity row missing for a mutation | mitigate | The trigger fires inside the same transaction as the data write; if the trigger fails, the data write rolls back. Test 4 proves the trigger fires |
| T-04-24 | Spoofing | actorId in activity row | mitigate | Trigger reads `request.jwt.claims ->> 'sub'`; the transaction wrapper sets this from the verified session. Test 5 proves it |
| T-04-25 | Information Disclosure | Local storage leaking saved view filter data | mitigate | The saved-views store no longer writes to localStorage; filter data is server-side only |
</threat_model>
