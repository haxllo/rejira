The optimistic UI (Plan 05) becomes the consistency story for the same user; the Realtime channel is the consistency story for *other* users in the same workspace.

**Step 1: Build `apps/web/hooks/useRealtimeIssues.ts`.**

```typescript
'use client';
import { useEffect } from 'react';
import { useRouter } from 'next/navigation';
import { useDebouncedCallback } from 'use-debounce';
import { subscribeToIssues } from '@/lib/realtime/subscriptions';
import { useIssues } from '@/lib/state/issues';

export function useRealtimeIssues(workspaceId: string) {
  const router = useRouter();
  const revalidate = useDebouncedCallback(() => { router.refresh(); }, 200);
  
  useEffect(() => {
    if (!workspaceId) return;
    const sub = subscribeToIssues(workspaceId, () => revalidate());
    return () => sub.unsubscribe();
  }, [workspaceId, revalidate]);
}
```

**Step 2: Build `apps/web/hooks/useRealtimeComments.ts`.**

This is a different shape — it patches the local store directly (no refetch), so the comment stream in the drawer updates instantly.

```typescript
'use client';
import { useEffect } from 'react';
import { subscribeToComments } from '@/lib/realtime/subscriptions';
import { useComments } from '@/lib/state/comments'; // Zustand store for comments (per-issue)

export function useRealtimeComments(issueId: string) {
  useEffect(() => {
    if (!issueId) return;
    const sub = subscribeToComments(issueId, (payload) => {
      if (payload.eventType === 'INSERT') {
        useComments.getState().append(payload.new as Comment);
      } else if (payload.eventType === 'UPDATE') {
        useComments.getState().replace(payload.new as Comment);
      } else if (payload.eventType === 'DELETE') {
        useComments.getState().remove((payload.old as { id: string }).id);
      }
    });
    return () => sub.unsubscribe();
  }, [issueId]);
}
```

The `useComments` store is a per-issue Zustand store keyed by `issueId`. Create it in `apps/web/lib/state/comments.ts`:

**Step 3: Build `apps/web/hooks/useRealtimeNotifications.ts`.**

```typescript
'use client';
import { useEffect } from 'react';
import { subscribeToNotifications } from '@/lib/realtime/subscriptions';
import { useNotifications } from '@/lib/state/notifications';

export function useRealtimeNotifications(userId: string) {
  const refetch = useNotifications((s) => s.refetch);
  const setUnreadCount = useNotifications((s) => s.setUnreadCount);
  
  useEffect(() => {
    if (!userId) return;
    const sub = subscribeToNotifications(userId, async (payload) => {
      // On any change, refetch the unread count from the server
      await refetch();
      // Optimistically update the local count
      if (payload.eventType === 'INSERT') setUnreadCount((c) => c + 1);
      else if (payload.eventType === 'UPDATE' && (payload.new as Notification).readAt && !(payload.old as Notification).readAt) {
        setUnreadCount((c) => Math.max(0, c - 1));
      }
    });
    return () => sub.unsubscribe();
  }, [userId, refetch, setUnreadCount]);
}
```

The `useNotifications` store is created in `apps/web/lib/state/notifications.ts`:
- `notifications: Notification[]`
- `unreadCount: number`
- `setUnreadCount(count | ((prev: number) => number))`
- `setNotifications(notifications)`, `append(notification)`, `markReadLocally(id)`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Supabase Realtime (WebSocket) | The WebSocket connection is authenticated via the session cookie; Supabase Realtime applies RLS per subscriber. A user can only receive rows from workspaces they are a member of |
| Server (trigger) → Realtime publication | The trigger writes the data; the publication broadcasts it; the browser receives only what RLS allows. No app-side filter needed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-35 | Information Disclosure | Cross-workspace Realtime leak | mitigate | Supabase Realtime applies RLS per subscriber. A user in workspace X subscribing to the `workspace:X` channel cannot receive rows from workspace Y. RLS is the only guard |
| T-04-36 | Spoofing | Fake Realtime events | mitigate | Supabase Realtime events come from the Postgres WAL; they cannot be spoofed by a client |
| T-04-37 | Denial of Service | 10k WebSocket connections from a single client | mitigate | The provider opens exactly one channel per workspace; one channel per workspace means one WebSocket per workspace per browser tab |
| T-04-38 | Information Disclosure | Notification payload includes private issue details | mitigate | The notification row's `metadata` is populated by the trigger; it includes the issue key + title (which the user can already see) but not the description body. If the user does not have access to the underlying issue, RLS hides the notification too (RLS on notifications filters on user_id) |
| T-04-39 | Denial of Service | Rapid re-renders from debounce failure | mitigate | The 200ms debounce on useRealtimeIssues coalesces multiple changes into one router.refresh() |
| T-04-40 | Tampering | WebSocket connection from an unauthenticated client | mitigate | The Supabase browser client reads the session token from the cookie; without a valid session, the WebSocket is rejected. RLS denies the subscriptions |
</threat_model>
