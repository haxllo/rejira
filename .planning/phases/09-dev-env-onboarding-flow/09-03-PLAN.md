**Critical finding (pre-review):**
The onboarding page at `/onboarding` exists and is fully built, but there is NO redirect from post-sign-in to `/onboarding` for new users. After sign-up → email verification → sign-in, the user lands on `/inbox` (via `callbackURL: '/inbox'` in `signUp.email()` and the root `/` → `/inbox` redirect). The onboarding wizard is effectively unreachable through the natural sign-up flow. This is the most important issue to document.

**Review scope:**
- Clarity: Is each step's purpose immediately obvious?
- Navigation: Are Back/Skip/Continue affordances clear?
- Edge cases: Empty states, error states, loading states, validation UX
- Accessibility: Tab order, focus management, aria labels
- Polish: Animation timings, spacing, text content
- Responsiveness: Mobile layout
- Error handling: What happens when API calls fail (even if stubbed)?
</interfaces>

  <action>
    Create a structured UI/UX review document. Systematically evaluate every aspect of the onboarding flow.

    Read all onboarding and auth components listed in context. For each, evaluate:

    **1. Flow Completeness & Routing (CRITICAL)**
    - Trace the complete post-sign-up path:
      - Sign up → "Account created! Sign in →" → user clicks link → sign-in page
      - Sign in → middleware approves session → redirects to `/inbox`
      - Is there ANY code path that redirects new users to `/onboarding`?
      - Check: `signUp.email()` callbackURL, middleware, workspace layout, RequireAuth
      - Document the finding: the onboarding page is unreachable through natural flow

    **2. Each Wizard Step — Clarity Review**
    For each step (welcome, create-workspace, invite-team, create-project, done):
    - Is the heading clear about what this step does?
    - Does the description text explain WHY the user should take this action?
    - Are input labels present and meaningful?
    - Is placeholder text helpful or confusing?
    - Are validation messages clear and helpful?
    - Are error states handled (and displayed clearly)?
    - Are loading states indicated?
    - Can the user get stuck (required fields without clear indication)?

    **3. Navigation & Affordances**
    - Back button: always present and correctly positioned?
    - Skip button: visible and clear about what skipping means?
    - Continue/Next button: enabled/disabled states clear?
    - Progress indicator: does it show step position and completion?
    - Can user see how many total steps remain?

    **4. Visual Polish**
    - Consistent spacing with design system tokens
    - Spring motion on transitions (should use `ease-spring` cubic-bezier)
    - Focus rings visible on all interactive elements
    - Color contrast meets WCAG AA
    - Mobile layout: does it break at narrow widths?

    **5. Edge Cases**
    - What if workspace creation API call fails? (currently stubbed)
    - What if slug is taken? (currently only client-side debounce)
    - What happens if user refreshes mid-wizard? (state is lost — local React only)
    - What if user has 0 workspaces but the "skip" banner shows? (edge case check)

    ```markdown
    |---|------|-------|----------|-----|

    | # | Scenario | Current Behavior | Expected Behavior |
    |---|----------|-----------------|-------------------|

    - Total issues found: X
    - Critical: X
    - High: X
    - Medium: X
    - Low: X
    ```

    Use severity levels:
    - **Critical**: Blocks the user from completing onboarding
    - **High**: Significant confusion or friction
    - **Medium**: Noticeable but not blocking
    - **Low**: Polish or nice-to-have
