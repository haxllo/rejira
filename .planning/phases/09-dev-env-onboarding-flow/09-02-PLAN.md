<objective>
Determine and implement the email verification policy for developer environments: whether to skip or enforce email verification when running locally.

Purpose: In dev, email verification via ConsoleTransport prints a link to the terminal. This works but creates friction — developers must find and click a console link before they can sign in. Decide whether this is acceptable or whether we should skip email verification in dev (where security boundaries are different from production).

Output: Updated Better Auth configuration with documented dev policy, updated .env.example, improved ConsoleTransport logging.
</objective>

- **Skip in dev** (`requireEmailVerification: false` when `NODE_ENV=development`): Faster onboarding, no console hunting, but dev env diverges from prod behavior
- **Enforce in dev** (keep current behavior): Matches prod, tests verification flow, but adds friction to local dev
