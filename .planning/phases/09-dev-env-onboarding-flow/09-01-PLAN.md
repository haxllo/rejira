  <action>
    Create a structured audit document that traces the complete dev environment journey. For each step, document what the developer sees, what they need to know, and what could go wrong.

    Trace these paths end-to-end:

    **Path A: First-time setup (git clone → running app)**
    1. Clone repo
    2. `npm install` (workspace root installs `apps/web` deps)
    3. Copy `.env.example` → `.env.local` and configure values
    4. Supabase local stack (`supabase start`, `supabase db reset`)
    5. Database seed (`npm run db:seed`)
    6. Start dev server (`npm run dev`)
    7. Navigate to `localhost:3000` → see sign-in page
    8. Click "Sign up" → sign-up form

    **Path B: Sign-up and auth flow**
    1. Fill in name, email, password (min 12 chars)
    2. Submit → what happens? (check-email? direct to inbox? error?)
    3. Email verification: find link in console (ConsoleTransport)
    4. Click verify link → verify-email page → success → redirect to sign-in
    5. Sign in with credentials
    6. Where does user land? (inbox? onboarding?)

    **Path C: First workspace experience**
    1. After sign-in → home page
    2. Is there an onboarding prompt? (check if /onboarding is reachable)
    3. If user reaches /onboarding → 5-step wizard
    4. Wizard flow: welcome → create workspace → invite team → create project → done
    5. After completion → workspace landing page

    **Path D: Magic link flow**
    1. Sign-in page → "Send magic link" → check email (console)
    2. Click link → authenticated → landing page

    **Path E: OAuth flow (if configured)**
    1. Click Google/GitHub sign-in → OAuth redirect → callback → landing page

    **For each step, document:**
    - What the developer SEES (screenshots not needed — describe UI state)
    - What the developer NEEDS TO KNOW (env vars, console links, etc.)
    - What could CONFUSE or BLOCK the developer
    - The TIME COST (roughly: immediate / < 1 min / > 1 min)

    **Format the report as:**

    ```markdown
    # Dev Environment Setup Flow Audit

    ## Summary

    [Brief overview of findings]

    ## Complete Flow Map

    ### Step 1: Clone & Install
    ...
    ### Step N: First workspace

    | # | Step | Friction | Severity | Impact | Recommendation |
    |---|------|----------|----------|--------|---------------|

    ## Quick Wins (Easy fixes that improve flow)

    ## Environment Configuration Audit
    - Are all env vars documented with examples?
    - Are there any hardcoded dev-only values?
    - Is the .env.example accurate?

    ## Recommendations
    ```
