**`docs/adr/001-nextjs-supabase-better-auth.md`**:
- Context: Needed realtime, RLS, vector search, auth. Convex was initially chosen but didn't support pgvector, RLS, or pg_cron.
- Decision: Next.js 16 + Supabase Postgres + Drizzle ORM + Better Auth
- Alternatives considered: Convex (rejected — no Postgres features), Firebase (rejected — vendor lock), Prisma (rejected — slower migrations, edge issues), Auth.js (rejected — less TS ergonomics)
- Consequences: One DB, one ORM, one migration story; three connection strings per env

**`docs/adr/002-rls-tenancy.md`**:
- Context: Multi-tenant app needs workspace isolation. App-side helpers are error-prone.
- Decision: Row Level Security on every table; `auth.jwt() →> 'sub'` identifies the user; workspace-scoped policies
- Consequences: No `requireRole()` helpers in app code; pgTAP proves RLS in CI; even buggy app code can't leak data

**`docs/adr/003-mock-to-drizzle.md`**:
- Context: Phases 0-1 built with in-memory mock data. Phase 2 creates real Postgres schema. Phase 4 replaces all mock reads.
- Decision: Keep `lib/mock/` as dev fixtures; Drizzle replaces all data access in Phase 4; `lib/mock/` deleted after Phase 4
- Consequences: 4-phase migration (schema → auth → queries → cleanup); CI gates each phase
