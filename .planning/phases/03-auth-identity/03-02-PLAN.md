<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → OAuth provider | OAuth redirect through Google/GitHub; user authenticates on external domain |
| Magic link email → `/api/auth/magic-link/verify` | One-time token in email URL; if intercepted, attacker gains session |
| TOTP code → `/api/auth/two-factor/verify` | 6-digit code; limited to 3 attempts before lockout |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-09 | Spoofing | OAuth callback | mitigate | Better Auth validates state parameter and PKCE; redirect URI whitelisted |
| T-03-10 | Information Disclosure | Magic link token | mitigate | 256-bit random token, 15-min expiry, single-use, hashed at rest, HTTPS-only |
| T-03-11 | Elevation of Privilege | Account linking | mitigate | Only link accounts with matching verified email; require re-auth to unlink |
| T-03-12 | Denial of Service | 2FA verification | mitigate | 3 wrong TOTP codes → 15-min lockout; backup codes bypass lockout |
| T-03-13 | Information Disclosure | Backup codes plaintext | mitigate | Displayed once; hashed at rest with SHA-256; no recovery — user must regenerate |
| T-03-14 | Spoofing | Session hijacking | mitigate | IP + UA hash binding; new-device email on unrecognized device; revoke from session list |
| T-03-15 | Repudiation | Session revocation | accept | Sign-out events logged by Better Auth internally; audit_log integration in Plan 03-05 |
</threat_model>
