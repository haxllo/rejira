<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → `/api/auth/*` | Untrusted input: email, password, tokens cross this boundary to Better Auth handlers |
| Client → `apps/web/lib/auth/server.ts` | pg.Pool connection to Supabase is server-only; client never accesses DB directly |
| Email templates → Resend API | User-controlled email content (name) rendered in templates; must escape |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | `sign-in-form.tsx` | mitigate | Better Auth validates credentials against hashed password in Postgres; no client-side bypass possible |
| T-03-02 | Tampering | Session cookie | mitigate | httpOnly, secure, sameSite=lax, `__Host-` prefix in prod; JWE cookie cache signed with BETTER_AUTH_SECRET |
| T-03-03 | Information Disclosure | `verify-email` token | mitigate | 256-bit random token, single-use, 24h expiry, hashed at rest |
| T-03-04 | Elevation of Privilege | `require-auth.ts` | mitigate | Server-side session check on every protected route; redirects unauthenticated to /sign-in |
| T-03-05 | Spoofing | `reset-password` flow | mitigate | Email link with 1h expiry, single-use token; invalidates all existing sessions on reset |
| T-03-06 | Information Disclosure | `server.ts` env vars | mitigate | BETTER_AUTH_SECRET and DATABASE_URL_SESSION never exposed to client; server-only import enforced |
| T-03-07 | Denial of Service | `/api/auth/sign-up/email` | mitigate | Rate limit 30 reqs/min per IP via Better Auth built-in rate limiter (upgraded to Upstash in Plan 03-05) |
| T-03-08 | Repudiation | Auth events | accept | Audit log (`audit_log` table) written via databaseHooks in Plan 03-05; for now, Better Auth logs to Postgres |
</threat_model>
