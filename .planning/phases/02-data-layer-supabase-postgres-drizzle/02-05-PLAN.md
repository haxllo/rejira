The activity row's actor_id is set from the session via current_user_id(), not from the caller's input, so a user cannot forge activity events."

RLS in plan 02-04 restricts reads to workspace members; the trigger itself doesn't filter. Mitigate by ensuring the trigger function only runs in the same transaction as the data change (so a failed insert rolls back the activity row too)."

<objective>
Add the 6 hand-authored SQL migrations that implement Postgres triggers and DB functions: `updated_at` auto-update, issue numbering, activity log emission, user mirror sync, workspace defaults, and full-text search vector.

Purpose: Triggers enforce invariants at the DB level (the last line of defense) and free the app from repetitive work (writing activity log rows, computing issue keys, mirroring users). They also enable the activity log to capture every change in the same transaction as the mutation.
Output: 6 new SQL files, ~30 triggers, and a fully-functioning local DB that responds to mutations by writing activity rows, computing issue keys, and updating timestamps.
</objective>
