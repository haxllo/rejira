<task type="auto">
  <name>task 1: install Supabase CLI, init local stack, commit config</name>
  <files>supabase/config.toml, supabase/migrations/.gitkeep, .gitignore</files>
  <action>
1. Install Supabase CLI. On macOS: `brew install supabase/tap/supabase`. On Windows (this dev box): use the GitHub release binary or `scoop install supabase`. Verify with `supabase --version`.
2. From the repo root, run `supabase init`. This creates `supabase/config.toml` and `supabase/migrations/`. Commit the empty `supabase/migrations/` directory by adding a `.gitkeep` file inside.
3. Open `supabase/config.toml` and pin image versions for `[api]`, `[db]`, `[realtime]`, `[storage]`, `[studio]`, `[inbucket]` to the same Supabase release (e.g. `supabase/postgres:15.6.1.145`). Pinning ensures every contributor and CI gets the same stack.
4. Add `supabase/.branches/` and `supabase/.temp/` to `.gitignore` so per-branch DB caches and the temp CLI dir are excluded. Confirm `.env*` is already excluded (it is, per the existing `.gitignore`).
5. Run `supabase start`. It will pull Docker images the first time; this takes 1-3 minutes. Confirm Postgres 15 is up by running `supabase status` and verifying the `DB URL` line points at `127.0.0.1:54322`.
  </action>
  <verify>
<automated>supabase status | grep -E "(API URL|DB URL|Studio URL|DB version)"</automated>
  </verify>
  <done>`supabase start` succeeds; `supabase status` shows the API URL, DB URL, DB version `15.x`, Studio URL (`http://127.0.0.1:54323`), Inbucket URL, Realtime URL, and Storage URL; `supabase/config.toml` is committed with pinned image versions.</done>
</task>
