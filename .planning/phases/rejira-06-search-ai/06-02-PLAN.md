Upgrade the command palette to use the hybrid search backend, add a semantic/AI search mode, and build an AI triage dialog that suggests assignee, labels, priority, and project when creating an issue.

### Task 2: Create AI triage API route

<read_first>
- apps/web/app/api/ (existing route handler patterns)
- apps/web/lib/ai/client.ts
</read_first>

<action>
Create `apps/web/app/api/ai/triage/route.ts`:

- POST handler that accepts `{ issueTitle: string, issueDescription?: string, workspaceId: string }`
- Reads AI key from workspace settings
- Calls OpenAI with structured output (function calling or response_format):
  ```typescript
  const completion = await client.chat.completions.create({
    model: 'gpt-4o-mini',
    messages: [
      { role: 'system', content: 'You are a Jira-like issue triage assistant. Suggest: priority (none/low/medium/high/urgent), assignee (suggest a name or "Unassigned"), labels (array of 1-3 label strings), project suggestion (string). Return as JSON.' },
      { role: 'user', content: `Title: ${title}\nDescription: ${description || '(none)'}` }
    ],
    response_format: { type: 'json_object' },
  });
  ```
- Return `{ suggestions: { priority, suggestedAssignee, labels, suggestedProject, explanation } }`
- Handle errors: no key → 400, OpenAI error → 502, rate limit → 429
- Track cost: call a helper `recordAICost(workspaceId, model, tokens)` that increments `monthly_ai_spent_cents`

Export a shared helper `recordAICost` to `apps/web/lib/ai/cost.ts`.
</action>

<acceptance_criteria>
- `apps/web/app/api/ai/triage/route.ts` exists with POST handler
- Returns structured JSON with suggestions
- `apps/web/lib/ai/cost.ts` exists with `recordAICost`
- Route handles no-key, OpenAI error, and rate limit cases
</acceptance_criteria>

<action>
