### Task 4: Create migration for embeddings index

<read_first>
- supabase/migrations/0000_initial_schema.sql (existing vector setup)
- supabase/migrations/0009_tsvector.sql (existing tsvector setup)
</read_first>

<action>
Create `supabase/migrations/0018_embeddings.sql`:

- Ensure the `issues` table has `embedding vector(1536)` column (it may already exist from 0000 — use IF NOT EXISTS)
- Create IVFFlat index on `embedding` with `lists = 100` for cosine similarity search:
  ```sql
  CREATE INDEX IF NOT EXISTS idx_issues_embedding ON issues USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
  ```
- Create a function `match_issues_by_embedding` for pgvector similarity search:
  ```sql
  CREATE OR REPLACE FUNCTION match_issues_by_embedding(
    query_embedding vector(1536),
    match_threshold float DEFAULT 0.7,
    match_count int DEFAULT 20,
    p_workspace_id text DEFAULT NULL
  )
  RETURNS TABLE(
    id text,
    title text,
    description text,
    status text,
    priority text,
    similarity float
  )
  LANGUAGE plpgsql
  AS $$
  BEGIN
    RETURN QUERY
    SELECT
      i.id, i.title, i.description, i.status, i.priority,
      1 - (i.embedding <=> query_embedding) AS similarity
    FROM issues i
    WHERE i.embedding IS NOT NULL
      AND (p_workspace_id IS NULL OR i.workspace_id = p_workspace_id)
      AND 1 - (i.embedding <=> query_embedding) > match_threshold
    ORDER BY i.embedding <=> query_embedding
    LIMIT match_count;
  END;
  $$;
  ```

Create `supabase/migrations/0019_search_triggers.sql`:

- Create a trigger function `update_search_vector()` that updates `search_vector` on title/description change:
  ```sql
  CREATE OR REPLACE FUNCTION update_search_vector()
  RETURNS trigger
  LANGUAGE plpgsql
  AS $$
  BEGIN
    NEW.search_vector := to_tsvector('english', COALESCE(NEW.title, '') || ' ' || COALESCE(NEW.description, ''));
    RETURN NEW;
  END;
  $$;
  ```
- Create trigger on `issues` table (before insert or update of title, description):
  ```sql
  CREATE TRIGGER trg_issues_search_vector
    BEFORE INSERT OR UPDATE OF title, description ON issues
    FOR EACH ROW
    EXECUTE FUNCTION update_search_vector();
  ```
</action>

Create `apps/web/lib/db/queries/search.ts`:

- Export `searchIssuesHybrid(query: SearchQuery): Promise<SearchResponse>`
- Implementation:
  1. BM25 path: Use Drizzle `sql` template to run `ts_query` against `search_vector` column with `plainto_tsquery('english', text)`, ordered by `ts_rank(search_vector, query)`:
     ```typescript
     const tsQuery = sql`plainto_tsquery('english', ${query.text})`;
     const bm25Results = await db.execute(sql`
       SELECT id, title, description, status, priority, project_id,
              ts_rank(search_vector, ${tsQuery}) as rank
       FROM issues
       WHERE workspace_id = ${query.workspaceId}
         AND search_vector @@ ${tsQuery}
       ORDER BY rank DESC
       LIMIT ${limit}
     `);
     ```
  2. Semantic path: If workspace has AI key configured, call `match_issues_by_embedding` via raw SQL with embedding from `generateEmbedding`
  3. RRF: Merge results with Reciprocal Rank Fusion → `score = 1 / (k + rank)` where k=60
  4. If text is empty, return recent issues (fallback)
  5. Apply workspace_id filter for RLS
- Export `searchIssuesBM25(query: SearchQuery): Promise<SearchResponse>` (BM25 only)
- Export `searchIssuesSemantic(query: SearchQuery): Promise<SearchResponse>` (semantic only)
</action>
