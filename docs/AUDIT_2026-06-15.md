## Findings (in order of severity)

### CRITICAL — security / data integrity

#### 1. RLS policies missing on 12+ tables
`supabase/migrations/0023_org_plugin_alignment.sql:364-375` drops **every** RLS policy on **every** table. `0024_org_rls_rewrite.sql` only recreates policies for the 4 org-plugin tables (`workspaces`, `memberships`, `invitations`, `teams`). The remaining tables — `issues`, `projects`, `comments`, `notifications`, `labels`, `cycles`, `cycle_issues`, `saved_views`, `activities`, `attachments`, `issue_assignees`, `audit_log` — have **no RLS policies**. The original `0003_rls_policies.sql` referenced dropped columns and was never rewritten. Migration `0027_fix_column_refs_after_camelcase_rename.sql` only touches storage + audit_log.

Phase 2 plan §2D promised 8 RLS tests; only 4 of those tables are protected.

**Fix:** write a new hand-authored `supabase/migrations/0037_rls_recreate.sql` that recreates the `0003` policies against the new `"workspaceId"` / `"userId"` column names. Do not edit `0003`.

#### 2. `lib/db/queries/search.ts` uses dropped column names
Raw SQL references `i.workspace_id`, `i.project_id`, `i.embedding`, `i.search_vector` (snake_case). After `0023`, `issues."workspaceId"` is camelCase quoted. `searchIssuesBM25` and `searchIssuesSemantic` at `queries/search.ts:127-144, 164-183` will error at runtime. The search API at `app/api/search/route.ts` is wired but unusable.

**Fix:** rename references to `"workspaceId"`, `"projectId"`, `embedding`, `search_vector`. Only `workspaceId` was renamed; the rest are still snake_case.

#### 3. `lib/realtime/workspace-provider.tsx` subscriptions are no-ops
Every `postgres_changes` handler is `() => {}` (lines 39-68). The channel opens, the WebSocket stays alive, but no store gets updated. `useRealtimeIssues.ts`, `useRealtimeComments.ts`, `useRealtimeNotifications.ts` exist but never fire `setOne` / `setNotifications` / `setComments` when a row changes. Two-browser collaboration does not work.

**Fix:** wire the callbacks to invalidate or optimistically update the Zustand stores (`useIssues`, `useNotifications`, `useComments`).

#### 4. `lib/db/rsc.ts` queries bypass the JWT-claims transaction wrapper
`withTransaction()` at `lib/db/transaction.ts:19-35` sets `request.jwt.claims` via `set_config(...)` so RLS sees the current user. But every read query in `rsc.ts` (`getIssuesForActiveWorkspace`, `getProjects`, `getCycles`, `getLabels`, `getUsers`, `getNotifications`, `getSavedViews`, `getMemberships`, `getRecentActivities`, `getActivitiesForObject`) calls `db.select()` directly with **no transaction**, no claim set. RLS will deny rows (or fall through to `service_role` if that key is in the connection string). When item #1 above is fixed, every read will start returning 0 rows until this is also fixed.

**Fix:** wrap reads in `withWorkspaceTransaction(workspaceId, async (tx) => ...)` (the helper already exists in `lib/db/transaction.ts:37`) and return plain objects — or extract a `setClaims(db)` helper called once per request.

#### 5. `notifications.userId` and the user-identity model are broken end-to-end
Drizzle schema (`schema/notifications.ts:11`): `userId: bigint references users.id`. DB after 0023: `notifications."userId"` is still `bigint`. Better Auth identity is `text` (in `public."user"`, created by `0022_better_auth_schema.sql`). The Drizzle `users` table is a **legacy mirror** that the seed populates but Better Auth never writes to. `rsc.ts:148-160` does a `SELECT id FROM users WHERE external_id = …` subquery — `u_aria` from the seed is unreachable from a real session.

The seed (`lib/db/seed.ts:11, 33, 45, 63, 70, 115, 181, 197, 209, 219, 228`) inserts `BigInt(0n)` and `BigInt(uid)` into `workspaces."ownerId"` and `memberships."userId"` which are `text` columns — Drizzle will throw on the type cast. The seed is **dead code** today.

**Fix (app-side only, no DB churn):** delete `seed.ts`, delete the legacy Drizzle `users` table from the schema barrel, and source demo data from `public."user"` (Better Auth) after a programmatic sign-up in CI / dev.

### HIGH — frontend / backend alignment

#### 6. `lib/mock/` is type-only but still on disk
`apps/web/lib/mock/issues.ts`, `projects.ts`, `cycles.ts`, `labels.ts`, `users.ts`, `inbox.ts` are 1-line re-exports of `@/lib/db/types`. `index.ts` only re-exports types. `mock-cleanup.test.ts` (passing) proves cutover is done. The directory is a footgun — every `rg "lib/mock"` in CI costs time.

**Fix:** delete `apps/web/lib/mock/`. The path alias `@/lib/db/types` already replaces it.

#### 7. `apps/web/lib/db/migrations/0000_next_crusher_hogan.sql` is stale
Has snake_case columns matching the **pre-rename** schema. The 37 `supabase/migrations/*.sql` are the source of truth. Running `drizzle-kit generate` against the current Drizzle schemas would create a divergent migration that the Supabase CLI would then reject.

**Fix:** delete `apps/web/lib/db/migrations/` and document `supabase/migrations/` as the single migration path. `drizzle-kit` is still useful for type inference, just not for SQL generation.

#### 8. Search page ignores the API
`app/(workspace)/search/page.tsx:35-44` filters `useIssues` client-side. The full hybrid search backend (BM25 + pgvector + RRF) at `app/api/search/route.ts` + `lib/db/queries/search.ts` is wired but never called. Two search engines; only the dumb one ships.

**Fix:** either delete the page and route ⌘K through the API, or wire the page to `GET /api/search?text=…&mode=hybrid`.

#### 9. Cycle board and grouped-list drag do nothing
`components/views/cycle-board.tsx:96-101` and `components/views/grouped-list.tsx:127-148` call `useUI.getState().endDrag()` and return. No mutation, no `apply()`, no `useIssues.reorderInGroup` / `moveToStatus`. The optimistic update path in `lib/state/issues.ts:38-89` is wired but no caller invokes it on drop.

**Fix:** call `apply({ run: () => setStatusAction(...), undo: () => useIssues.getState().moveToStatus(...) })` from the `onDragEnd` handler.

#### 10. Drizzle schemas are inconsistently named
After 0023, the actual DB has `"workspaceId"` everywhere but other columns are still snake_case. The Drizzle code reflects this in a mixed way:

- CamelCase column strings: `workspaces.ts`, `memberships.ts`, `invitations.ts`, `teams.ts`, `workspace-security-policy.ts`
- Snake_case column strings: `users.ts`, `issues.ts`, `notifications.ts`, `issue_assignees.ts`, `comments.ts`, `cycles.ts`, `project_members.ts`, `attachments.ts`, `activities.ts`

The mapping is correct for what the DB looks like, but it is a landmine for new contributors.

**Fix:** add a comment at the top of `schema/index.ts` documenting the rule. No code change needed.

#### 11. Cycle page hardcodes `velocity = 42`
`app/(workspace)/projects/[key]/cycles/[id]/page.tsx:31` — `const velocity = 42;`. Real data is the last completed cycle's average. Remove or compute.

### MEDIUM — missing / broken

#### 12. Settings hub is over-built
`app/(workspace)/settings/page.tsx:25-74` lists 8 hub cards. Several redirect to sub-pages that don't exist:
- `/settings/account/security`
- `/settings/account/sessions`
- `/settings/account/data`
- `/settings/account/notifications`

These return 404. Either ship the sub-pages or collapse the hub to a single-page layout.

**Existing sub-pages:**
- `/settings/account` (profile, password, email) — `app/(workspace)/settings/account/page.tsx`
- `/settings/account/profile` — exists
- `/settings/members` — exists
- `/settings/ai` — exists (likely)
- `/settings/security` — exists (likely)

**Missing:** sessions, data export, notifications sub-pages.

#### 13. Activity log is never written by app mutations
The trigger in `0006_activity_log_triggers.sql` only fires on raw DML. Drizzle mutations in `lib/db/actions/issues.ts`, `actions/projects.ts`, etc. do not call `emitActivity(...)` or insert into `activities`. The activity feed (`app/(workspace)/projects/[key]/activity/page.tsx` + `home/page.tsx:73`) will be empty for all real changes.

**Fix:** add an `activities` insert to each action, or install a `pg_trigger` on the relevant tables that fires on UPDATE/DELETE/INSERT (the second approach is closer to the original Phase 2 plan).

#### 14. `reorderIssues` and `linkIssues` are no-ops
`lib/db/actions/issues.ts:328, 364` — return `true` with `console.warn`. Reorder is the most common drag-drop action; it is stubbed. Link is documented as Phase 5 but Phase 5 is complete.

**Fix:** either implement against the (missing) `issue_links` table or remove the action and the corresponding hook call.

#### 15. `notifications.refetch()` is called but not implemented
`components/inbox/inbox-stream.tsx:60` calls `useNotifications.getState().refetch()` on a realtime INSERT. `lib/state/notifications.ts` has no `refetch` method. The subscription on line 57-62 would error.

**Fix:** either implement `refetch` (POST to `/api/db/notifications`) or simplify to `useNotifications.getState().prepend(newNotif)`.

#### 16. Search joins via legacy `users` table
`lib/db/queries/search.ts:139, 177` — `LEFT JOIN users u ON u.id = (SELECT unnest(i.assignee_ids) LIMIT 1)`. `assignee_ids` is `integer[]` of internal ids. The `users` table is the legacy mirror; assignee names from real Better Auth sessions will be missing. Document or fix the assignment model.

### LOW — minimalism / UI

#### 17. `components.json:13` says `iconLibrary: "lucide"`
`PLAN.md §4` says **no Lucide, no framer-motion, use `@animate-ui/icons` + `motion/react`**. Animate UI itself ships Lucide-derived icons. The convention is muddled.

**Fix:** tighten the rule in `CONVENTIONS.md` and add a lint rule banning `from 'lucide-react'`.

#### 18. Settings hub: collapse to a single page or left rail
8 cards in a 2×2 grid with chevrons is heavy. Linear-style: left rail with section names, right pane with content. Removes the hub page entirely.

#### 19. Home page is 4 cards in a 2×2 grid
`app/(workspace)/home/page.tsx:36-95` — `My open issues`, `Up next`, `Recent activity`, `Active projects`. Each card is `border + bg-surface-1 + p-4 + uppercase tracking-tight label`. Reduce to: "My open" list (top), "Recent activity" (bottom). Two stacked sections, no card chrome. Saves ~50 lines.

#### 20. Search page has decorative Tips sidebar
`app/(workspace)/search/page.tsx:107-114` lists `is:` / `by:` prefixes that aren't implemented. Remove the sidebar or wire the syntax. Either way, a sidebar on a search page is over-built.

#### 21. ViewHeader re-renders on every list query
`ViewHeader` is in every page. Each page fetches the same data the layout already fetched (`users`, `labels`, `projects`, `issues`). The layout hydrates them into Zustand stores via `WorkspaceDataHydrator`. The pages then re-query the DB. Drop the per-page re-fetch when the data is in the store.

#### 22. Project landing page uses a query it then filters against
`app/(workspace)/projects/[key]/page.tsx:23` does `getIssuesForActiveWorkspace({ projectId, status: 'todo', limit: 100 })` then line 30 filters by `status !== 'done' && status !== 'cancelled'`. The `status: 'todo'` constraint is wrong (only todo issues are returned, but the filter is for non-done). Wasted query.

#### 23. Card / Stat / Empty components duplicated inline
The "Card / Stat / NavLink / Empty" helpers inside `projects/[key]/page.tsx:166-203` are re-implemented in every page. Extract to `components/primitives/`.

## Database — leave alone

Per direction, do **not** touch migrations or the legacy `users` schema. The Drizzle ↔ DB drift (#10) and stale Drizzle migration (#7) are real but cosmetic — `db:reset` works against `supabase/migrations/`. The fix is in the **app code** (search.ts raw SQL, rsc.ts transaction wrapping, realtime-provider wiring), not new migrations.

The one exception: the missing RLS policies (#1) require a new hand-authored `supabase/migrations/0037_*.sql`. This is a security regression, not stylistic — without it, the DB is effectively wide open once #4 is fixed.
